# 论文手主工作流

## 目录

1. 确定定位与产物
2. 恢复项目状态
3. 接收建模手与代码手材料
4. 通过论文手理解关
5. 建立章节合同与职责边界
6. 设计和审计标题树
7. 建立论文证据槽
8. 生成可人工深改的论文母稿
9. 减少模板化并学习当前稿件
10. 人工接管、局部回修与终审
11. 快速模式

## 1. 确定定位与产物

把论文手模式作为“技术成果转论文”的控制层，不把它当作独立于建模和代码的文字加工。先帮助论文手理解并筛选队友成果，再组织为可核验、可继续人工修改的论文。

默认交付 `论文母稿`，不宣称得到无需人工判断即可提交的最终成稿。用户明确要求最终润色、格式交付或仅做审计时，按其当前授权调整产物。

区分五种工作模式：

| 模式 | 主要产物 | 不应越过的边界 |
|---|---|---|
| 思路讲解 | 论文手理解卡 | 不自动写正文 |
| 章节骨架 | 标题树、章节职责、证据槽 | 不提前填充整章 |
| 论文母稿 | 可编辑正文和单独备注 | 不编造缺失结果 |
| 局部回修 | 指定范围的最小修改 | 不重写锁定部分 |
| 终审 | 分级问题与最低限度修法 | 未获授权不直接改稿 |

## 2. 恢复项目状态

每次续作前读取赛题、最新实际论文、建模手方案、代码和运行结果、已有图表、引用材料、优秀论文、格式规则及用户最近反馈。不要把上一次 Agent 输出自动当成最新稿。

至少维护以下状态：

- 当前比赛、题目、问题和章节；
- 当前工作模式与本轮交付边界；
- 最新认可稿及其时间或版本标识；
- 已写入、已确认、已锁定和禁止修改的范围；
- 已废弃方案、旧图和被否决表述；
- 当前项目的标题、段落、公式、图表和交付格式参数；
- 缺失证据、待向建模手或代码手确认的事项。

按以下优先级解决材料冲突：

> 当届官方规则与模板 > 用户当前明确指令 > 最新认可稿与锁定范围 > 已核验模型、代码和结果 > 用户稳定偏好 > 优秀论文共性 > 通用默认

## 3. 接收建模手与代码手材料

不要直接复制队友说明。先把交接材料整理为一条可检查的链：

> 建模结论 -> 数学对象与假设 -> 代码实现 -> 运行结果 -> 公式、图、表证据 -> 论文位置

接收建模手材料时，确认：

- 当前方案回答哪个小问，输入和输出是什么；
- 为什么选择该路线，哪些替代方案已放弃；
- 关键变量、假设、目标、约束和评价是什么；
- 哪些细节可以为可解释性补充，哪些改变会偏离队友主线；
- 前后问接口、单位和不确定性是否一致。

接收代码手材料时，确认：

- 使用的数据、代码、配置、随机种子和运行版本；
- 哪些结果真实运行过，哪些只是计划或中间试验；
- 公式与代码变量、函数和输出文件如何对应；
- 图表是候选、用户选中、已插入、已废弃还是等待最终版本；
- 警告、异常、失败试验和口径变化是否会影响论文。

发现队友方案存在问题时，优先做检查、补链和最小改动。报告原方案、问题证据、建议调整和影响范围；不要未经确认另起一套模型。

## 4. 通过论文手理解关

在写正式正文前输出论文手理解卡，帮助用户达到“能用自己的话说明”的程度。卡片至少回答：

1. 这一问解决什么，最终要交付什么；
2. 模型为何合适，核心机制是什么；
3. 输入、输出、变量、参数、假设和约束是什么；
4. 关键公式每一项表示什么、单位和下标是什么；
5. 公式如何映射到数据字段、代码变量和运行结果；
6. 哪些结论已证实，哪些仍待确认；
7. 最容易被评阅者或答辩老师追问什么。

把公式分成两层：

- `理解层`：允许直观解释、完整符号定义、必要推导、边界情形和代码对应；
- `论文层`：只保留定义核心对象、目标、关键约束、求解关系、评价或不确定性所需的公式。

不要把理解层的全部推导机械搬入论文。也不要为了压缩公式而删除决定模型含义和可复现性的核心关系。详细公式标准读取 `paper-and-visualization.md`。

## 5. 建立章节合同与职责边界

写每章前建立章节合同，明确：

- 本章回答什么问题，直接答案放在哪里；
- 上游输入和下游输出是什么；
- 本章允许首次引入哪些概念；
- 哪些内容已在问题分析、模型准备或前章说明，禁止重复；
- 哪些概念不得提前出现或“剧透”；
- 哪些公式、结果、图、表和引用构成本章证据；
- 哪些段落由用户亲写或已经锁定；
- 当前篇幅、标题层级和交付格式要求。

让各功能部分各负其责：

| 部分 | 主要职责 |
|---|---|
| 问题重述 | 说明题目要求什么 |
| 问题分析 | 说明怎样拆解以及为什么走这条路线 |
| 模型准备 | 说明共用数据、假设、符号和基础关系 |
| 模型建立 | 定义核心变量、机制、目标和约束 |
| 模型求解 | 说明影响结果的算法、参数和执行过程 |
| 结果分析 | 报告数值、读图并解释其题目意义 |
| 模型检验 | 说明结果在什么意义下可信 |
| 模型评价 | 分析当前方法的真实优缺点 |
| 模型推广 | 说明适用边界和迁移映射 |

完成初稿后执行跨章节重复审计。优先整节合并或删除，再做句子级压缩。

## 6. 设计和审计标题树

先设计标题树，再写大段正文。为每个标题标明职责、所需证据和预计篇幅。

采用以下个人默认；只有官方模板或用户当前明确要求可以覆盖：

1. 父标题已经设置子标题时，父标题后直接进入第一个子标题，不保留游离正文。需要过渡时，把它融入第一个实质子节；确有独立任务时再设置有意义的编号小节。
2. 用二级标题承载一个主要建模阶段或论证模块。
3. 同一二级标题下存在两个及以上有实质差异的并列步骤、机制、检验或结果时，考虑使用三级标题。
4. 不把复杂技术章全部平铺为二级标题，也不为追求数量强行拆出三级标题。
5. 避免孤立三级标题、过细或过密三级标题，以及比本节主逻辑更抢眼的三级标题。
6. 默认不用四级标题；只有模板要求或复杂度确实无法由段落组织时再使用。
7. 默认不机械设置“本章定位”“本章小结”“本问结论”。把必要过渡和结论融入实质小节。
8. 使用简洁、功能明确的学术名词短语。避免一句完整结论充当标题，也避免脱离当前稿件语境的生造术语。
9. 对照当前问题号、章号和既有编号方式，检查标题跳级、编号错位和旧章号回流。

标题层级表达逻辑，不追求表面整齐。问题分析、评价、推广和建议等较短部分可只使用二级标题；模型建立、求解和检验等技术部分按实际内部结构决定是否使用三级标题。

## 7. 建立论文证据槽

在标题树确认后，为每节登记：

- 需要引用的建模结论；
- 对应数学定义或公式；
- 对应代码运行与结果文件；
- 准备使用的图、表和决定性数字；
- 必要文献及其可支持范围；
- 本节最终应得出的直接结论；
- 尚缺内容和责任人。

正文只使用已证实材料。把不确定项、待确认参数、待插图和给论文手的修改建议放入单独备注，不混入可直接粘贴的正文。

让每张图表承担一个明确论证任务。先盘点代码手已有候选，再判断是否需要重画；让用户明确选定后再嵌入正文。图、表和正文不要三次完整重复同一信息，按精确数值、趋势比较和版面效率选择最合适的载体。

## 8. 生成可人工深改的论文母稿

按已确认标题树分节生成，不因追求“一次完成”而覆盖整篇。母稿应当：

- 严格承接已确认的建模和代码逻辑；
- 延续最新稿的标题粒度、段落节奏、语气和编号方式；
- 使用真实变量、数值、图表和取舍推进论证；
- 让公式可编辑、符号先定义并与代码一致；
- 在图表出现前引入，在图表之后解释观察、意义和边界；
- 保留用户继续加入判断、删改和重组的空间；
- 把论文正文与内部备注分开交付。

用户只要求大纲、公式解释或局部正文时，只输出所需产物，不擅自扩写整章或整篇。

## 9. 减少模板化并学习当前稿件

先从用户最新稿的相邻内容提取项目级文风参数：

- 标题命名和编号方式；
- 每节段落数量和大致篇幅；
- 常用开头、论证顺序和句子长短；
- 公式、图、表与文字的比例；
- 用户已经否决的术语、句式和组织方式。

这些参数只服务当前项目，不固化为所有论文的永久规则。

按以下顺序减少模板化：

1. 删除空泛导语、机械小结、重复预告和重复定义；
2. 调整标题树、章节职责、段落合并和证据密度；
3. 用本题变量、数值、代码结果和真实选择替换抽象套话；
4. 再处理高频连接词、统一句长、宣传式评价、生造术语和反复的“不是……而是……”；
5. 复核修改没有改变技术含义、夸大证据或违反 AI 使用披露要求。

把优秀论文用于学习标题粒度、信息顺序、证据密度和图表嵌入方式，不复制其特色措辞、数值、参数、图形或未经本题验证的模型路线。

## 10. 人工接管、局部回修与终审

用户修改后，重新读取其实际成稿并把它设为唯一当前版本。记录哪些 Agent 草稿已经采用、修改、锁定或废弃。

执行局部回修时：

- 明确允许修改的章节、段落、公式、图表和格式；
- 保留用户亲写和已锁定内容；
- 只检查为保证一致性所必需的相邻范围；
- 防止旧标题、旧图、旧公式、旧数字和废弃方案回流；
- 修改后复核编号、交叉引用、符号和上下文衔接。

终审时分别检查：

1. 技术链：模型、公式、代码、运行结果和结论；
2. 结构链：标题层级、章节职责、跨章重复和逐问覆盖；
3. 证据链：数字、图、表、引用和不确定性；
4. 作者链：最新稿、锁定范围、人工判断和模板化表达；
5. 交付链：格式、渲染、支撑材料和当届合规。

详细清单读取 `final-audit.md`。

## 11. 快速模式

把常见短指令解释为：

- `先教我`：只生成论文手理解卡；
- `先给大纲`：只生成章节合同、标题树和证据槽；
- `直接写这一章`：内部完成理解、合同和标题树检查后，输出论文母稿；
- `只改这一段/这一节`：以最新稿为真执行局部回修；
- `降低 AI 味`：先做结构和证据审计，再做受限语言处理；
- `终审`：读取原题和最终材料，执行完整审计，不只做润色。
