## 1. 按任务规模使用

不要机械展示所有表格。短任务只保留必要字段；多问、多数据源、多人协作或长时间项目才使用完整台账。台账用于防止上下文漂移、静默改口径和结果失去来源，不用于制造文档数量。

## 3. 问题覆盖矩阵

```markdown
| 小问 | 题目动词 | 输入 | 输出 | 目标/约束 | 单位与范围 | 依赖 | 方法 | 证据位置 | 验证 | 直接答案位置 | 状态 |
|---|---|---|---|---|---|---|---|---|---|---|---|
```

状态可用：未开始、进行中、待决定、已运行、已验证、已成稿、已审计。

对多问任务补充接口表：

```markdown
| 上游小问 | 输出量 | 定义与单位 | 不确定性 | 下游小问 | 使用方式 | 接口核验 |
|---|---|---|---|---|---|---|
```

## 4. 证据台账

```markdown
| 编号 | 拟写论断或数字 | 状态 | 证据类型 | 文件/表/图/代码/文献位置 | 可写范围 | 待办 |
|---|---|---|---|---|---|---|
```

证据状态：

- 已证实：可由题面、实际数据、运行输出、已核验原文或用户明确决定定位；
- 待确认：有合理线索但尚未复核；
- 仅建议：尚未实施的模型、分析或写法；
- 不可写：无来源、与材料冲突或超出模型能力。

快速规则：摘要数字定位到正文，正文结论定位到输出或推导，图表定位到数据和脚本，引用定位到原文，建议定位到前文证据。

**证据：**

**影响：**

## 10. 让项目结构与规模相称

单一计算使用一个清晰脚本或 Notebook 即可。多问、多数据源或多人协作时可采用：

```text
project/
  data/
    raw/             # 只读原始数据
    interim/         # 可追溯中间数据
    processed/       # 建模数据
  src/
    common/          # 公共读取、校验与指标
    q1/ q2/ ...      # 各问模块
  configs/           # 参数、种子、路径和划分
  results/           # 机器可读结果与运行索引
  figures/           # 绘图代码、绘图数据和终稿图
  paper/             # 论文源文件与引用
  logs/              # 运行、决策、处理和异常记录
```

不因“规范”创建空目录和无用抽象。结构只服务于协作、审查和复现。
