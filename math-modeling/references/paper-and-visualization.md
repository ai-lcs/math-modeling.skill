## 1. 让结构服务题目

论文通常需要完成以下功能，但不必机械使用固定目录：

- 摘要；
- 背景与问题重述；
- 全局任务图或求解路线；
- 必要假设与符号；
- 数据说明和公共处理；
- 各问的模型、求解、结果、验证与直接答案；
- 整体评价、局限、改进和推广；
- 参考文献；
- 附录与支撑材料索引。

当多个小问共享数据和模型时合并公共部分；当方法差异大时在各问内分别分析。不要在摘要、全局流程、问题分析和模型章节重复同一段计划。

一个章节或标题必须有独立任务和足够实质内容。避免一句一段、两三个词单独列点、大量短小标题和每问完全相同的模板。

## 2. 最后写摘要，逐问形成闭环

摘要按信息功能组织：整体任务，然后逐问写任务、关键数据特征、方法、决定性结果、验证和最终回答，最后概括整体贡献与边界。

要求：

- 每问都能被评阅者快速定位；
- 保留少量决定性数字，不堆全部指标；
- 每个数字与正文、表格、图和代码输出完全一致；
- 不在摘要首次出现正文没有的方法、结果和创新；
- 不用“效果良好”“精度较高”代替指标和对照。

逐问正文自然推进：

> 问题需要 -> 数据或约束 -> 方法选择 -> 数学定义 -> 求解 -> 真实结果 -> 验证 -> 直接答案

终点是对题目的答案，不是一个公式或模型名称。

## 3. 写好各功能部分

### 背景与重述

- 只保留与本题对象和核心矛盾直接相关的背景；
- 引用涉及数量、机制和规则的外部事实；
- 重述保留对象、条件、约束、单位、时间范围和交付物；
- 不照抄冗长题面，不提前加入模型和答案。

### 问题分析

回答任务类型、输入输出、数据结构、核心困难、候选路线和问间联系。不要写算法百科，也不要重复后文所有公式和参数。

### 假设与符号

只保留模型真实依赖的假设。对每条假设说明为什么需要、在哪个公式使用、失效后影响什么。删除“忽略一切偶然因素”“数据真实可靠”等无法承担责任的万能假设。

符号表只收录反复出现、含义不直观或易混淆的数学对象。统一大小写、下标、向量、矩阵和单位，不把代码临时变量全部搬入。

### 模型建立与求解

- 先说明本题需要，再引出模型；
- 定义变量、参数、目标、约束、损失和边界；
- 解释公式在求解链中的作用；
- 给出经验参数的来源、范围或估计方法；
- 把代码流程转换为数学和算法逻辑，不逐行翻译程序；
- 写清影响结果的数据划分、初始化、停止条件、随机性和超参数；
- 不补写代码没有执行的标准化、交叉验证、调参、检验或灵敏度分析。

### 结果与讨论

区分：

1. 观察：图表或数值客观显示什么；
2. 解释：在证据允许范围内为什么可能如此；
3. 意义：怎样回答题目或影响后续决策；
4. 边界：不确定性、失效样本和适用范围。

不要复述每个单元格，不从相关性直接推出因果，不把视觉差异自动写成统计显著。

### 模型评价与推广

优点和缺点必须关联当前模型、数据和验证。按“原因 -> 影响 -> 改进”写局限。推广必须说明新场景与本题在变量、约束和机制上的映射，不列空泛行业清单。

### 参考文献与附录

- 只列真实、已阅读并在正文使用的来源；
- 核对作者、题名、载体、年份、卷期、页码或 URL；
- 让引用直接支持对应论断；
- 在附录开头列文件或内容索引，映射到题号、方法和正文图表；
- 说明输入、输出、环境、依赖、随机种子、关键参数和复现命令；
- 不把正文必须解释的核心模型藏在附录。

## 4. 保持公式与代码一致

保留定义变量、变换、模型、目标、约束、递推、评价和不确定性的必要公式。每个新符号先定义，公式前说明目的，公式后解释关键量。

检查：

- 标量、向量、矩阵、集合和随机变量的字体与含义；
- 上下标、括号、求和范围和维度；
- 单位和量纲；
- 目标函数方向和约束符号；
- 公式编号和正文引用；
- 论文公式、伪代码和实现是否同一算法。

不要为了显得数学化加入未使用公式，也不要把黑箱模型伪装成未经推导的简单显式方程。

## 5. 用表格表达精确数值

优先用表格呈现样本量、参数估计、模型比较、分组边界、方案参数、分类指标和敏感性结果。

- 使用可编辑的清晰表格，不截图；
- 表题、列名、单位、样本范围和统计口径完整；
- 小数位与测量精度和比较需要匹配；
- 同列精度统一，数值对齐；
- 关键数字与程序输出一致；
- 正文引用并解释决定性差异；
- 大型中间表移至附录或支撑材料。

如比赛或学校要求三线表，按其格式执行。

## 6. 让每张图回答一个问题

### 先写图表任务卡

内部明确：对应小问、图要回答的问题、数据文件与字段、样本范围、单位、预期事实、正文引用方式和是否存在会改变结论的处理。

### 选择最直接的图形

| 目的 | 优先图形 | 谨慎或避免 |
|---|---|---|
| 时间趋势 | 折线图、区间带 | 无依据平滑、面积装饰 |
| 类别比较 | 点图、条形图、箱线图 | 三维柱状图、多类别饼图 |
| 分布 | 直方图、ECDF、箱线图、小提琴图 | 只画均值柱 |
| 拟合与预测 | 真实-预测、残差、误差分布、区间 | 只放一条“拟合很好”曲线 |
| 分类 | 混淆矩阵、PR/ROC、阈值曲线、校准图 | 只报 accuracy |
| 敏感性 | 参数曲线、龙卷风、热力图 | 过密雷达图 |
| 优化 | 收敛、可行性、目标-约束权衡 | 只报最优点 |
| 空间与网络 | 地图、邻接或流图、热力图 | 无地理或拓扑含义的布局 |

### 禁止误导性数据表达

未经实质确认，不得：

- 删除或隐藏异常与不利结果；
- 平滑、插值、补点、聚合或改变样本范围；
- 用截断轴、对数轴、双轴或非线性尺度改变视觉判断；
- 改变有意义的时间、空间或类别顺序；
- 只展示有利模型和指标；
- 用面积、体积、透视和颜色暗示不存在的差异或因果；
- 把模拟、预测和实测数据混为一类。

## 7. 实际运行、看图并导出

按以下顺序：

1. 从明确的结果文件读取最终绘图数据；
2. 生成验证图，核对轴、类别、单位、矩阵方向和关键数值；
3. 生成论文版，统一字体、字号、线宽、颜色语义、图例、留白和子图编号；
4. 实际查看最终图片，修复遮挡、截断、重叠、异常空白和不可辨颜色；
5. 对照表格和模型输出复核关键数值；
6. 保存绘图代码、最终绘图数据、PNG 和 PDF 或 SVG。

视觉要求：

- 以论文最终栏宽或页面宽度检查可读性；
- 轴名、单位、图例、色条、阈值和区间定义完整；
- 相同模型或类别跨图保持同一颜色和线型；
- 不依赖颜色作为唯一编码，兼用线型、标记或直接标签；
- 连续色图优先感知均匀方案，发散色图必须有有意义中心；
- 避免 `jet`、装饰性渐变、默认九宫格和无信息阴影；
- 图内标题不与论文图题重复；
- 不使用 IDE、聊天窗口或屏幕截图作为终稿图。

## 8. 处理参考图、已有图与结论边界

### 参考图转代码

把参考图当作信息组织样例，不当作数值来源：

1. 拆解横纵轴、变量映射、布局、颜色、标注和比较逻辑；
2. 判断图形是否适合当前数据、任务和论文尺寸；
3. 只迁移可泛化的结构，不复制独特装饰、作者性设计或无关复杂度；
4. 使用用户真实数据重新计算和绘制，不从图片猜测、数字化或反推缺失数值，除非用户明确要求合法的数据数字化任务；
5. 核对类别顺序、矩阵方向、颜色映射、视角、坐标尺度和图例，防止镜像或错配；
6. 对有版权的来源保留必要引用，不把结构借鉴声称为原创证据。

数据图必须由可核验数据和可复现代码生成。不要用黑箱式文生图生成、补绘或“美化”统计曲线、数据点、误差带和模型结果。

### 修改已有图

- 数据、单位、映射或结论错误：先报告证据和影响，再修正实质内容；
- 字体、留白、图例、清晰度和排版问题：在授权范围内直接修正；
- 图形不合适但信息等价：生成优化版，并保留原版供比较；
- 需要改变样本、口径、尺度、排序或模型集合：暂停受影响部分并请求决定；
- 修改后重新运行或重建图，核对绘图数据、表格、模型输出和正文。

### 完成单图结论审计

对进入论文的关键图明确记录：

- 图能够支持的事实；
- 图不能单独证明的结论；
- 最可能的误读；
- 与表格、模型输出和正文是否一致；
- 原图、绘图数据、生成代码和优化版之间的对应关系。

## 9. 消除模板化，而不是伪装人工

通过本题变量、约束、数据现象、参数来源和真实取舍形成作者性。删除算法百科、万能背景、重复总结和无证据赞美。

避免：

- 机械重复“首先、其次、最后”；
- 每段结尾都写“提高准确性”“具有重要意义”；
- 每问复制同样小标题和句式；
- 用同义词替换、故意语病或粗糙图形规避 AI 检测；
- 把优秀论文的特色措辞、结构图、参数和结果移植到本题。

可以学习优秀论文的信息顺序、证据密度、模型接口和审稿视角，但必须用本题数据重新论证，并主动检查优秀论文自身的数字冲突、弱验证、错误公式和过度结论。
