# 提交前全链路审计

## 1. 先固定审计对象

- [ ] 确认题目、附件、论文、代码、数据、配置、结果和支撑材料的最终版本。
- [ ] 记录官方规则与格式规范的核验日期和来源。
- [ ] 冻结或标记正在审计的版本，防止审计中静默替换输出。
- [ ] 从原题逐问审计，不只检查稿件自身是否顺畅。

## 2. 题目覆盖与逻辑闭环

- [ ] 每一问、每个子任务和每项条件都有明确回答位置。
- [ ] 输出类型与题目一致：数值、分类、排序、方案、解释或证明没有互相替代。
- [ ] 每问形成任务、方法、结果、验证和直接答案闭环。
- [ ] 后问真实使用前问结果时，接口定义、单位和不确定性一致。
- [ ] 没有用背景、模型介绍或流程图代替作答。
- [ ] 摘要和结论覆盖全部问题。

## 3. 题意、假设与符号

- [ ] 关键题意解释有题面依据或已记录决定。
- [ ] 没有遗漏附件中的限制、时间、空间、单位和边界条件。
- [ ] 每条假设在模型或计算中实际使用。
- [ ] 假设不与题面、数据、领域规律或其他假设冲突。
- [ ] 临时假设和 Agent 建议没有被写成事实。
- [ ] 符号、下标、单位、向量和矩阵全文一致。

## 4. 数据与预处理

- [ ] 数据来源、版本、观测单位、表间关系和样本范围明确。
- [ ] 字段、单位、标签、时间和空间范围与论文一致。
- [ ] 缺失、重复、异常、筛选、合并和样本量变化可追溯。
- [ ] 删除、填补、变换、缩放、编码、聚合、抽样和特征构造有依据和影响记录。
- [ ] 异常值没有仅因统计规则被自动当作错误删除。
- [ ] 没有目标、未来、对象、空间邻近或全数据预处理泄漏。
- [ ] 训练、验证、测试和全样本结果被清楚区分。

## 5. 模型与数学表达

- [ ] 每个模型解决的具体任务、输入和输出明确。
- [ ] 变量、参数、目标、约束、损失、边界和评价指标均定义。
- [ ] 参数有题面、数据、文献、估计或敏感性依据。
- [ ] 模型假设与数据结构和样本量相容。
- [ ] 公式、伪代码和代码实现一致。
- [ ] 目标方向、约束符号和单位正确，约束确实在代码中生效。
- [ ] 组合模型的功能不重复，接口真实衔接，相对基线有可测价值。
- [ ] 没有只为创新或数量加入未使用模型。

## 6. 代码、运行与复现

- [ ] 核心代码已在最终数据和配置上实际运行。
- [ ] 环境、依赖、入口、路径、随机种子和运行命令明确。
- [ ] 预处理、数据划分、模型和评价能从干净入口按顺序重现。
- [ ] 关键中间量、警告、收敛、配置和输出已保存。
- [ ] 手工修改数据、图表或输出已记录；没有无法追踪的二次改数。
- [ ] 论文声称的调参、交叉验证、检验和敏感性确实在代码中执行。
- [ ] 支撑材料中的程序完整、可运行，并与最终论文相符。

## 7. 结果与验证

- [ ] 关键数字能定位到最终运行输出或可复核计算。
- [ ] 摘要、正文、表格、图和结论中的数字、方向、排名、样本数和单位一致。
- [ ] 模型与简单基线在公平条件下比较。
- [ ] 验证划分匹配时间、分组、空间、类别不平衡或优化结构。
- [ ] 性能指标同时说明数据划分、样本量、评价方法和不确定性。
- [ ] 已检查残差、混淆、失效样本、可行性、收敛或对应诊断。
- [ ] 灵敏度和稳健性结论来自真实扰动，不是建议被写成结果。
- [ ] 模拟、训练表现、内部验证和外部验证被明确区分。
- [ ] 异常完美、高度整齐、边界集中或不稳定结果已有诊断。
- [ ] 结论没有把相关写成因果、把重要性写成现实贡献或把局部结果推广到全部场景。

## 8. 图表、表格与版面

- [ ] 每幅图表服务一个明确问题并在正文中被解释。
- [ ] 图题、表题、轴、单位、图例、色条、样本范围和统计口径完整。
- [ ] 图表由最终数据和最终代码生成，关键值与结果表一致。
- [ ] 没有隐藏异常、不利模型或不利指标。
- [ ] 没有误导性截轴、双轴、面积、体积、透视、色阶或无说明对数尺度。
- [ ] 图片不是截图，缩放到论文实际尺寸后仍清晰。
- [ ] 表格可编辑、精度统一，未用图片替代表格。
- [ ] 图、表、公式、章节编号和交叉引用准确。
- [ ] 页数、摘要页、目录、匿名、文件格式和大小符合当届规则。

## 9. 写作、引用与原创性

- [ ] 每段有明确论证任务，没有大段算法百科和万能背景。
- [ ] 摘要最后写，只包含正文已有的模型、数字和结论。
- [ ] 结果分析区分观察、解释、意义和边界。
- [ ] 模型优缺点与真实机制、数据和验证相关，不使用空泛赞美。
- [ ] 所有文献真实存在，元数据和正文支持内容已核对。
- [ ] 每条关键领域或方法论断有合适来源，所有列出文献均在正文使用。
- [ ] 没有复制优秀论文的特色措辞、模型理由、数值、图表或流程图。
- [ ] 没有通过同义词替换、故意语病或粗糙排版伪装人工写作。

## 10. 合规与支撑材料

- [ ] 已读取当届官方参赛规则、论文规范、提交须知和 AI 使用规定。
- [ ] AI 使用的工具、版本、日期、目的、关键交互、采纳与人工修改按规则记录。
- [ ] 正文标注、参考文献、AI 使用详情和支撑材料满足当届要求。
- [ ] 引用、外部数据和公开资料均有来源。
- [ ] 论文和支撑材料没有身份、学校、赛区或其他禁止信息。
- [ ] 支撑材料文件列表与实际压缩包一致，没有过期结果、临时文件或无关大文件。
- [ ] 文件命名、格式、大小、压缩方式和提交入口符合通知。

## 11. 准备答辩与责任链

- [ ] 队伍能逐问解释任务、模型、数据处理、关键结果和直接答案。
- [ ] 能说明为什么选择当前模型、基线怎样、复杂模型带来什么真实增益。
- [ ] 能解释异常样本、失败案例、局限和最敏感假设。
- [ ] 能从论文数字追溯到脚本、配置和输出。
- [ ] 能准确说明 AI 在哪些环节提供帮助、哪些判断由队伍完成、哪些内容经过人工修改和验证。

## 12. 分级输出审计结论

### 必须修正

列出会造成任务缺失、数学错误、数据失真、泄漏、不可复现、虚构依据、规则违规或结论改变的问题。给出准确位置、证据、影响、最低限度修法和需重跑模块。

### 建议修正

列出会削弱验证、解释、引用、图表可读性或评阅体验的问题。

### 可选优化

列出不改变实质结果的语言、版式、额外对照或次要扩展。

最终状态只使用：

- 通过审计，可交付；
- 存在非实质性问题，修正后可交付；
- 存在实质性问题，已暂停等待决定。
